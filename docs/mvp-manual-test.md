# MVP 人工验收

使用真实但非敏感的嵌入式学习主题执行下列步骤：

1. 在 Codex 中询问“FreeRTOS Queue 是什么？”，确认可直接获得简洁概念解释。
2. 在同一会话继续询问“Mutex 和 Queue 应该如何选择？”，确认学习台不输出正式教师协议或计划，而是索要最小上下文。
3. 填写目标“为项目中的事件传递选择正确机制”以及源码路径 `src/app/message_task.c`，确认学习台恢复第一性原理、证据边界、项目映射、费曼挑战和反事实问题。
4. 设置 `LEARNING_WORKBENCH_VAULT` 为目标 Vault。
5. 确认 `领域/嵌入式` 已存在。
6. 使用 `goal.json` 创建“FreeRTOS Queue 阻塞与唤醒”的预览，确认没有任何文件被写入。
7. 使用 `--confirm-write` 创建目标，确认出现五份 Markdown 文件和隐藏状态文件。
8. 提供自己的 Markdown 笔记、B 站时间段、博客链接、受限飞书链接引用和一个源码路径。
9. 提交包含手写笔记链接的 `submission.json`，掌握度选择 `0`。
10. 确认 `04-复习队列.md` 包含次日复习，`02-学习计划.md` 包含补救任务，`学习记录/` 包含提交内容。
11. 运行 `learning due`，确认可以恢复待复习项。
12. 运行 `npm run check`、`npm test -- --run` 和插件校验。

下列情况必须失败且不能产生越界文件：不存在的领域、`../` 目录逃逸、同名学习目标第二次创建、缺失确认标记的写入。
