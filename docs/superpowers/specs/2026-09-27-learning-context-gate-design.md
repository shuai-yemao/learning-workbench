# 学习上下文渐进门禁设计

## 目标

保留一次性快速概念问答的即时性；当同一会话已经出现第二个属于同一领域、但主题不同的概念问题时，学习台必须先确认最小学习上下文，随后才开始正式的闭环学习辅助。

## 范围与边界

- `user-confirmed`：单个快速概念问答不进入强制门禁，可直接得到简洁解释。
- `user-confirmed`：同一领域的第二个独立概念问题触发门禁。
- `user-confirmed`：门禁未满足时，只说明缺少的信息并提供模板；不生成正式教学、学习计划、项目结论或 Obsidian 写入预览。
- `user-confirmed`：门禁满足后，恢复既有的第一性原理、知识关联、项目映射、费曼挑战、对立视角、实践与复习闭环。
- 不新增自动抓取网页、Bilibili、飞书或项目文件的能力；受限资料仍只记录用户提供的链接、摘录或摘要。
- 不将“同领域”简单等同于关键词相同。领域由会话中已回答的概念及其关系判断；无法可靠判断时，老师必须先询问领域，而不是猜测。

## 方案比较

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 每个问题都收集上下文 | 严格但打断快速问答 | 不采用 |
| 只在用户明确说“开始学习”时收集 | 轻量但漏掉连续学习 | 不采用 |
| 会话内渐进门禁 | 第一次直接回答；第二个同领域独立问题进入上下文收集 | 采用 |

## 状态与判定

```text
QUICK_ANSWER
  ├─ 首个概念问题 → 直接简洁回答，并标记领域/可能关联
  └─ 同一领域的后续独立概念问题 → CONTEXT_REQUIRED

CONTEXT_REQUIRED
  ├─ 缺少主题或问题、目标、依据 → 输出模板并停在这里
  └─ 三项完整 → FORMAL_LEARNING

FORMAL_LEARNING
  → 执行既有教师协议与学习闭环
```

“独立概念问题”指新的概念、机制、对比或项目选择；对当前概念的澄清追问不累计为另一个概念问题。相同概念换一种表述也不触发门禁。

## 最小上下文

门禁触发后，必须收集下列三项：

```yaml
领域: 例如，嵌入式 / FreeRTOS 并发
当前主题或问题: 例如，Queue、Mutex 与 Task Notification 如何选择
当前目标或任务: 例如，能为项目中的事件传递选择正确机制
至少一项依据:
  - 自己的笔记摘录或路径
  - 资料链接及具体范围
  - 项目源码路径、diff、日志、测试或测量现象
```

前两项与“至少一项依据”共同构成可进入正式学习的最小上下文。材料链接只作引用；未经用户提供的受限文档内容不可被当作证据。

## 实现边界

1. 增加一个纯函数的上下文判定模块：输入已分类的会话问题和当前输入，输出 `quick_answer`、`context_required` 或 `formal_learning` 以及缺少字段。它是自动化测试的公共 seam。
2. 由学习台 Skill 使用同一判定规则，负责以自然语言归类概念与向用户收集上下文。
3. CLI 维持档案创建、提交与复习的职责；它不保存聊天历史，也不替代 Agent 的会话归类。
4. 更新输入契约和使用文档，使人工使用、Skill 行为和判定模块的规则一致。

## 错误处理与验证

- 无法判断领域：请求用户提供领域，不把问题强行归到某个领域。
- 同一概念的澄清：保持快速问答，不能因重复措辞误触发门禁。
- 已触发门禁但缺少目标或依据：只列出缺项与模板。
- 测试公共 seam：首问快速回答、第二个同领域独立概念触发、跨领域不触发、澄清追问不触发、上下文完整后进入正式学习。
