# 快速概念问答

帮助用户用最小必要信息解决当前概念疑问。由当前宿主 Agent 回答；本 Skill 定义回答范围与长度，不自带资料查询或状态工具。

## 入口与职责

- 用于“是什么”“有什么用”“有什么区别”“为什么会这样”的局部问题，以及“简单说”“快速解释”“只给结论”等明确要求。
- 不因主题专业或用户连续提问而自动升级为完整课程。连续问答与同概念澄清继续保持本模式，除非用户希望深入学习或已明确要练习、理解检查。
- 用户明确要求逐步学会、深入推导、结合项目系统分析或进行练习时，转入 `knowledge-point-learning`，保留当前疑问，不重新索要整体计划。
- 用户要求规划范围、顺序、深度与整体方法时，转入 `learning-method`。明确指定的 Skill 和本轮长度要求优先于按关键词猜测。

## 回答方式

1. 第一行直接给定义、结论或关键区别。
2. 只补足当前问题需要的内容：目的、机制、一个具体例子、一个关键边界或易混点。默认最多三个要点，不为凑满数量添加内容。
3. 概念比较适合时使用小表格；涉及公式时说明必要变量、单位与成立条件；需要代码时只给支撑结论的最小片段。
4. 用户已经得到答案时直接结束。仅当歧义会改变答案时，询问一个必要澄清；不要把教学提问当作每次回答的结尾。

默认正文不超过 300 个中文字符，通常一至三个短段即可；公式、代码或表格也保持最小。用户明确要求更详细、完整推导或多个例子时，以该要求为准，必要时进入知识点学习。可靠回答确实需要较长条件说明时优先保证准确，简短说明原因。

短回答也必须正确：不能删掉决定结论成立的关键条件，不能只给术语、口号或误导类比。

## 不自动展开的内容

除非用户明确要求，不输出整体目标收集表、行业方案调研、完整教师协议、学习计划、记忆安排、思维导图、费曼挑战、实践任务、复习队列、总结建档或写入预览。

不要为了回答一个概念而要求先提供笔记、项目路径或学习目的。项目事实确实需要源码或配置时，先说明通用机制与所缺证据，不能猜测该项目的实际实现。

## 上下文与证据

- 使用已经提供的领域和语境。术语有多种含义时，能从上下文确定就直接回答；不能确定且答案差异明显时问一个澄清问题。
- 优先读用户提供的具体材料；涉及版本、标准、行业做法或不确定的专业事实时，按宿主能力查证并给可回查出处，不虚构引用。
- 解释通用概念时不机械列出证据等级；涉及项目结论时清楚区分已读取源码、用户描述、推测与尚未验证的行为。
- 不把简短解释或用户说“懂了”记为已经通过掌握度检验，不声称安排了复习或完成了归档。

## 转入其他 Skill

切换依据是用户想得到的产出，而不是提问次数。转入知识点学习时沿用：当前概念、已回答结论、卡住的位置、已有例子和证据。转入整体指导时沿用用户已表达的用途与目标。

相应 Skill 不可用时说明只能按当前规则回答，提供必要交接信息，不假称已启动其他 Skill 或保存状态。
