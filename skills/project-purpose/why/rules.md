# 为什么阶段规则

> 状态：草稿模板
>
> 用户确认前，本模板不得成为具体项目的正式规则记录。
>
> 本文件只约束“为什么阶段”，不负责具体项目选择和执行设计。

## 1. 当前项目范围

- 项目名称：待用户确认
- 项目类型：学习 / 工程开发 / 面试准备 / 论文写作 / 作品集 / 能力建设 / 其他
- 当前阶段：为什么阶段
- 当前规则版本：v0.1
- 更新时间：待填写
- 用户确认状态：未确认

## 2. 本阶段目标

本阶段只回答：

> 我为什么要推进这件事？

本阶段形成一个用户暂时接受的“当前工作目的”。它不是绝对真实目的，需要在后续实践和现实反馈中继续验证。

## 3. Agent 可以做什么

- 复述用户已经确认的信息；
- 识别活动、工具、学习对象、结果、问题、需要和目的；
- 指出目的之间的冲突；
- 识别当前最关键的模糊点；
- 每轮提出一个针对性问题；
- 整理候选目的和形成依据；
- 标记 `user-confirmed`、`confirmed`、`inferred`、`unverified`；
- 保留目的版本差异；
- 输出可审查的理由摘要；
- 提醒用户决定目的及其优先级。

发送回复前，必须确认本轮没有输出项目推荐、周计划、任务清单、模块树、技术路线、工具比较、采购清单或学习路线。

## 4. Agent 不能做什么

- 替用户宣布已经发现绝对真实目的；
- 把工具、活动、学习对象或项目结果直接当成目的；
- 自动指定 P1、P2、P3；
- 选择具体项目或技术平台；
- 比较具体工具；
- 推荐具体项目方案；
- 拆解项目节点；
- 设计模块或执行计划；
- 确定项目必须的 20% 内容；
- 在用户确认前正式写入本目录的项目记录。

即使用户同时要求“直接安排项目”或“给我执行计划”，也不能在为什么阶段顺带完成这些内容。具体项目、平台、工具和方案只能作为目的线索。

## 5. 目的形成顺序

```text
目的线索
→ 目的假设
→ 当前工作目的
→ 实践或现实反馈
→ 复盘
→ 修正目的
```

每次只推进当前最影响目的判断的一步。

## 6. 目的状态

| 状态 | 定义 | 是否代表最终正确 |
| --- | --- | --- |
| 目的线索 | 用户当前说出的愿望、活动、工具、问题或动机 | 否 |
| 目的假设 | Agent 根据现有证据整理出的可能目的 | 否 |
| 当前工作目的 | 用户暂时接受并愿意据此推进 | 否 |
| 经实践检验的目的 | 实践反馈提供了更强支持 | 否 |
| 已修正目的 | 根据新证据修正后的目的 | 否 |

## 7. 证据标签

| 标签 | 使用规则 |
| --- | --- |
| `user-confirmed` | 用户明确说出或明确确认 |
| `confirmed` | 有可回查记录或现实证据支持 |
| `inferred` | Agent 根据上下文推断 |
| `unverified` | 尚未验证 |

禁止把 `inferred` 或 `unverified` 改写成用户已确认内容。

## 8. 当前工作目的的最低字段

- 真实问题；
- 具体结果；
- 结果证据；
- 为什么现在推进；
- 不推进的代价；
- 暂不解决的内容；
- 目的形成依据；
- 当前未确认假设；
- 目的优先级；
- 复盘触发条件。

## 9. 目的优先级规则

正式目的最多三个：

- P1：当前最重要；
- P2：重要但低于 P1；
- P3：可选。

排序由用户决定。Agent 只能指出冲突和排序依据，不得代替用户排序。

## 10. 每轮提问格式

每轮只能问一个问题，并按以下顺序输出：

1. 已确认信息；
2. 唯一关键模糊点；
3. 该模糊点的影响；
4. 一个针对性问题；
5. 等待用户回答。

问题不得机械固定为“为什么”，也不得一次发出完整问卷。

## 11. 用户确认规则

用户确认表示：

> 我愿意暂时按照这个目的推进，并在实践中验证它。

用户确认不表示目的绝对正确、目的永久不变、Agent 已完全理解用户，或所有后续项目方案已经确定。

## 12. 写入规则

用户确认前：

- 只输出聊天草稿；
- 不把本模板复制或填充为具体项目的正式 `why/rules.md`；
- 不把项目目的模板复制或填充为具体项目的正式 `why/project-purpose.md`。

用户确认并授权写入后：

- 才能创建或更新正式记录；
- 记录用户确认内容和目的版本；
- 目的状态写成“当前工作目的”；
- 不得写成“最终真实目的”。

## 13. 复盘规则

每次实践或现实反馈后，检查：

- 是否解决了原问题；
- 是否产生预期变化；
- 用户是否仍愿意投入；
- 是否暴露出遗漏、误判或替代目的。

以下情况触发复盘：

- 行动无法服务原问题；
- 用户真正想改变的事情发生变化；
- 结果与预期不一致；
- P1～P3 发生变化；
- 现实约束发生重大变化；
- 目的过于宽泛；
- 目的只是工具、活动或表面任务。

## 14. 目的修订记录要求

每次修订必须保留：

- 原目的；
- 触发事件；
- 新证据；
- 原目的的问题；
- 新目的；
- 对项目范围的影响；
- 新版本号；
- 更新时间。

## 15. 本阶段停止条件

- 真实问题明确；
- 具体结果明确；
- 结果证据明确；
- 暂不解决内容明确；
- 推进时机明确；
- 不推进代价明确；
- 目的依据明确；
- 未确认假设已列出；
- 正式目的不超过三个；
- 用户自行确定了优先级；
- 用户愿意暂时按当前目的推进；
- 尚未进入具体项目和执行拆解。
