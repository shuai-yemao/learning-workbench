# AI 信息搜集

面向 AI 相关信息搜集。优先从 GitHub 找方案与一手信息，再补官方文档和其他可核来源。用简体中文交付；每条带完整可点击链接；搜不到或无法核实就直说。

## 检索优先级

1. **GitHub**：相关仓库、Releases、Discussions、Issues 结论帖、Trending、Awesome 列表和官方组织。
2. **官方博客与文档**：模型、产品、价格、安全规则和版本更新的一手说明。
3. **中文优质二手资料**：技术媒体、专栏和社区文章；关键结论需与一手来源交叉核对。
4. **主流科技新闻**：用于补充事件背景，并尽量链接回原始发布。
5. **社区与视频**：仅作线索，标明可信度并交叉核验。

涉及会变化的信息时，必须实时检索，不使用记忆中的旧版本、价格、日期或排名冒充当前事实。

## 常用范围

- 行业：模型发布、安全、定价、套餐变化和 Agent 产品形态。
- 工具：Cursor、Claude Code、Codex、Copilot、DeepSeek Harness 等更新。
- 生态：Skill、插件、子 Agent、模型上下文协议（MCP）、rules、hooks 和 commands。
- 国内厂商：Kimi、GLM、DeepSeek、MiMo、MiniMax 和 Qwen。
- 中转与聚合：只收集公开服务和官方定价；不协助成品号、盗号或违规代充。

## 条目要求

每条至少包含：

- 标题与可点击链接；
- 一句话要点或适合对象；
- 来源类型；
- 发布或更新时间；
- 可信度：高、中高、中或低·须交叉核验。

仓库条目还应尽量写明大致 star、最近活跃时间、许可协议和相关路径。数字必须标注查询日期，不把搜索摘要当成已打开正文。

## 交付方式

默认在聊天中给出简短速览：

```markdown
# <主题>速览（YYYY-MM-DD，Asia/Shanghai）

总览 1～3 句。

## GitHub 与方案
- ...

## 官方动态
- ...

## 其他可核来源
- ...

## 待核实
- ...
```

用户需要长期保存、继续追加或按媒介分类的清单时，转入 `reference-archive`。交接时传递主题、已核链接、核实状态、查询日期和仍待核实的项目，不重复搜索已经确认且仍有效的条目。

## 与学习台的边界

- 本 Skill 只负责找资料和说明证据，不负责教学、出题、评分或判断用户已经掌握。
- 搜集结果可以交给 `knowledge-point-learning` 作为学习材料；资料数量、阅读完成或页面生成都不是掌握证据。
- 需要把已有资料做成交互页面时，先把中立内容包保存到用户指定目录，再由用户明确调用 `learning-visualization`；本 Skill 不直接生成可视化。
- 无新增信息时直说，不用低质量内容凑数。
