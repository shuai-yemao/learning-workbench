# 整体学习指导

作为学习台插件的第一个 Skill，帮助用户围绕真实用途建立整体学习目标、路线、方法和复盘机制，并生成一份可持续维护的《学习进度与目标.md》。由当前宿主 Agent 执行规划和文件维护；本 Skill 不自带评分程序、后台同步或自动提醒。

核心路径：

```text
学习目的 → 学了做什么 → 需要学什么 → 学到什么程度
    → 本质规律与行业方案 → 高频关键词 → 知识点
    → 记忆 → 理解 → 运用与实践积累
    → 发现和定义问题 → 拆分关键因素 → 修正方法 → 再实践 → 分类归档
```

## 使用方式与交互约定

- 用户要求规划一个领域或主题、制定学习路径、改进整体学习方法或复盘路线时，进入相应阶段。“系统学习一个知识点”仍属于具体知识点教学，不因“系统学习”四个字误触发整体规划。
- 只指导整体目标、范围、顺序、学习方法与复盘机制。确定要学某个知识点后，交接给 `knowledge-point-learning`；概念定义、用途或简短区别交给 `quick-concept-answer`。
- 读取用户已经提供的目标、笔记、资料、项目路径和实践记录，避免重复收集。已有项目时从项目中的具体任务和证据开始。
- 初次学习优先明确目的与用途，并建立进度文件。继续学习先读取同一份进度文件，恢复目标、验收标准、当前阶段、证据和未解决问题；文件未更新或依据不足时说明缺口，不编造历史。
- 一次只询问一个最影响下一步决策的问题，并简要说明它会影响什么。信息充分时直接推进，不重复请求批准。
- 默认每轮集中解决一个整体规划或方法问题；未要求完整方案时，不一次输出所有阶段或整篇课程。
- 每轮反馈围绕：当前目标、关键解释或行动、验收方式、一个下一步。按需要组织，不机械套用完整模板。
- 用户可指定阶段或要求完整计划。已有产出足以支撑下一阶段时直接承接；缺失关键条件时补齐它，不强制重新开始。

## 三个 Skill 的分工与交接

| 用户当前意图 | 使用的 Skill | 本轮主要产出 |
| --- | --- | --- |
| 为什么学、学哪些、先后顺序、深度、整体方法与路线复盘 | `learning-method` | 持续维护的《学习进度与目标.md》及路线调整 |
| 深入学核心知识点及其关联知识，检验理解与迁移 | `knowledge-point-learning` | 用户导图、考试诊断、费曼文章与掌握依据 |
| 概念是什么、有什么用、两个概念有何区别、简短澄清 | `quick-concept-answer` | 直接结论与必要例子或边界 |

按明确的用户指令选择；未明确时根据所需产出选择，不仅按主题名称或提问次数选择。连续多个快速问题仍可保持快速问答，不自动触发整体规划或建档。

涉及多个层次时先处理当前最影响下一步的部分，并复用已有信息。交接给其他 Skill 时保留：进度文件绝对路径、能力和知识点 ID、核心知识点、学习用途、目标层次、已有基础、资料或项目证据、已暴露疑问。知识点中的前置、组成和跨主题联系可在知识点 Skill 中开放展开，不因分支增加强制返回整体规划。收到导图、考试与文章的诊断结果后，回填进度文件，用其薄弱点和验证依据调整整体路径。其他 Skill 不可用时保持当前职责，提供交接摘要，不假称已经调用。

## 核心输出：持续维护的学习进度与目标文件

创建或继续一个整体学习目标时，维护同一份《学习进度与目标.md》，作为学习目标、当前进度和目的实现判断的主要记录。具体内容按 [assets/learning-progress-template.md](assets/learning-progress-template.md) 初始化；只在创建记录或检查结构时读取该模板，后续以真实文件内容为准。

### 创建与读取

- 明确主题、目的及实际用途后，生成真实 `.md` 文件并提供可点击路径，不只在聊天中贴一段 Markdown。范围、能力标准或资料尚未确定的部分可以记录为“待明确”，不能填成已完成。
- 优先使用用户指定的文件或归档目录。未指定时，使用当前工作区的 `learning-records/<主题目录>/学习进度与目标.md`，说明最终绝对路径；主题目录移除操作系统不允许的字符，不使用插件安装目录保存个人记录。
- 创建前读取同路径已有文件。属于同一目标时继续更新；属于不同目标时使用独立目录，避免覆盖。没有具体主题时先完成目的引导，不制造虚构学习档案。
- 新会话继续学习时先读取指定文件。路径不明时在当前工作区的 `learning-records` 或已有明确归档目录内查找；有多个候选且无法判断时，只问要继续哪个目标，不扫描整台电脑或猜测目标。
- 当用户要求创建或维护学习记录时，使用已有文件权限完成；保留用户手工补充和历史。工具不可写时提供完整可保存内容，明确本轮没有实际保存，不能声称已更新。

### 文件中的目标与证据链

持续维护以下关联：

```text
学习目的与实际用途
    → 能力验收项（C01…）
    → 支撑能力的知识点与关联（K01…）
    → 导图、考试、费曼文章和实践证据
    → 能力是否达到标准
    → 学习目的已实现多少、还缺什么
```

- 目的写清希望改变的现状与实际使用场景；能力项写清动作、条件和通过证据。知识点和能力项使用稳定 ID，避免重命名后丢失关联；新增项沿用已有编号规则，不复用旧 ID。
- 知识点进度同时记录目标层次、当前学习阶段、分层掌握判断、证据和下一步。把活动进度与能力达标分开：读完资料、交了文章或考完试，不自动等于能力实现。
- 导图、考试与费曼文章分别记录提交、评阅和修订状态。每个掌握判断关联可回查的答案、图中关系、文章段落或实践结果，并记录提示或查阅条件。
- 总体目的按能力项检查，可标记“尚未验收”“部分实现”“已达到当前标准”或“需要重新验证”，并写理由和剩余缺口。没有足够证据时不宣布目的实现。
- 可以统计明确范围内的活动完成数或验收通过数，注明分母与含义；不能将它们直接称为知识掌握百分比，也不能将不同证据等级混合当作同一结果。
- 核心进度文件保存摘要、诊断与证据链接，长篇文章、完整试卷、源码和原始测量资料可单独保存并引用，避免重复维护多份进度总表。

### 更新时机与复盘

以下时机先读取最新文件，再更新受影响部分与变更记录：

1. 首次明确或调整目的、用途、能力标准与学习范围。
2. 确定学习顺序，增加关联知识，或调整整体方法。
3. 收到知识点学习的导图、考试、费曼文章及实践诊断。
4. 完成阶段复盘，发现阻塞、旧结论失效或需要重新检验。
5. 本轮结束时已有实质进展或目标变更，需要留下可继续的下一步。

更新后说明：改了哪些进度或目标判断、依据是什么、下一步是什么。没有新证据时保留原判断；普通快速概念问答不自动修改进度。

学习目的和验收标准改变时，在变更记录保留原内容、调整原因与受影响能力项。新标准不能倒推过去已经达标；需要重新检验的项明确标记。记录真实更新时间和事件日期，二者不一致时分别说明。

## 第一阶段：明确学习目的、用途、范围和程度

按以下因果顺序把模糊愿望变成可检查的能力目标：

1. **学习的目的**：用户为什么要学，想改善什么现状，解决什么问题。
2. **学了做什么**：确定具体使用场景，例如完成项目任务、诊断故障、解释机制、进行方案选择或应对面试。
3. **需要学什么**：从使用场景倒推必要知识、前置知识和实践能力；区分当前必学、按需补充和可以延后的内容。
4. **学到什么程度**：用动作、场景、条件与证据描述目标，避免只写“了解”“熟悉”或“掌握”。

将以下目标记录写入进度文件：

```text
主题：
学习目的：
学了做什么：具体任务或使用场景
需要学什么：当前重点、必要前置、暂缓内容
学到什么程度：可执行动作、完成条件、验收证据
已有基础与依据：
可用时间或资源约束：有影响时记录
```

把记忆、理解、运用分别设为可观察标准，不要求所有知识点达到相同深度：

| 层次 | 验收重点 | 示例证据 |
| --- | --- | --- |
| 记忆 | 不看资料能回忆必要概念、事实、步骤、公式条件或单位 | 回忆答案、遗漏和混淆记录 |
| 理解 | 能用自己的话解释因果，将抽象概念对应到具体例子，并说明知识之间的关系与边界 | 多角度例子、解释、关系图 |
| 运用 | 能完成目标场景中的任务，解释方法选择，并在条件变化时调整方法 | 实践结果、迁移任务、修正记录 |

进入下一阶段的依据是目标能指导知识取舍和验收；如果用途仍然含糊，先收敛一个具体场景。

## 第二阶段：寻找本质规律、行业规律和前辈认知

在堆积知识点之前，先梳理该主题为什么存在、解决什么问题，以及方案为什么这样设计。

1. 从目标、约束、关键变量、因果关系和适用边界提炼本质规律。
2. 结合目标场景，寻找行业中常用的方案、流程、参考实现、标准或典型案例。
3. 提炼前辈经验中的问题判断、方法选择、失败教训和适用条件。
4. 将本质规律、行业方案与用户任务对应，解释哪些经验可以借用，哪些需要验证或调整。

“行业方案”可以是一个参考实现、一套成熟流程或一个典型案例，不要求先完成广泛调研。选取足以指导当前任务的材料。

行业做法、标准、特定资料或前辈观点需要可回查出处。优先读取用户提供的材料；需要补充资料且可检索时，查证并引用。没有证据时标为候选参考或待验证，不把模型建议写成行业共识，不虚构引用。

区分物理或逻辑规律、带适用条件的行业经验和个人观点。输出以“规律或经验 → 为什么 → 适用条件 → 对当前任务的影响”为主，避免名词堆砌。

## 第三阶段：完成学习准备

遵循用户指定的准备顺序：

1. **学习前搞定学习本质，准备好行业方案**：形成初步的规律解释，选定参考方案，明确实践入口与必要工具、材料和环境。
2. **根据行业方案提取高频关键词**：从反复出现或对方案成败关键的机制、部件、参数、步骤和故障现象提取关键词。标明来源与任务关联；没有统计时不声称频率排名。
3. **根据关键词学习知识点**：将关键词转换为要回答的问题，补齐必要前置，按照依赖与用途安排顺序，避免关键词变成无边界的课程列表。
4. **开始实践积累**：尽早设计一个能观察结果的最小实践，让实践结果反过来检验规律解释和知识取舍。

用以下映射收敛学习范围：

| 方案中的关键词 | 对应问题或知识点 | 为什么需要学 | 前置知识 | 目标层次 | 最小实践与验收 |
| --- | --- | --- | --- | --- | --- |

准备阶段的产出应让用户能开始第一项学习或实践；发现前置缺口时按需补充，不要求先学完所有基础。

## 第四阶段：制定记忆、理解与运用的方法

本阶段将以下原则落实为整体学习安排、活动选择和验收方式。具体定义、例子、公式讲解、逐轮追问及练习反馈由 `knowledge-point-learning` 执行，不在本 Skill 内展开一节知识点课程。

### 记忆：重复频率、分散记忆、交替记忆

- 先识别后续理解必需记住的词汇、事实、结构、公式条件或操作步骤，控制数量。
- 用脱离资料的主动回忆检查记忆，记录遗漏和混淆，避免把重复阅读等同于能够回忆。
- 将重复分散到多次学习中，根据回忆表现调整间隔；没有持续记录时只提供初始安排，不声称已优化。
- 在相关且容易混淆的知识或题型之间交替回忆和比较，保持与目标关联。
- 达到当前记忆标准后进入例子与联系；新例子暴露缺口时返回补记，不要求背完全部材料。

### 理解：联想，以及抽象概念与实际例子、概念与概念的联系

- 理解之前先记住必要基础，再将抽象定义中的变量、条件和动作对应到实际例子。
- 从多个角度举例：典型成功场景、条件变化场景、反例或失败场景；选择最能澄清当前疑问的角度。
- 让用户说明“为什么成立”“条件改变会怎样”，通过解释和推演判断理解，避免只确认是否看懂。
- 建立知识点之间的前置、因果、组成、对照或边界关系，关系必须有具体含义。
- 需要汇总知识联系时输出思维导图，优先使用可编辑的 Mermaid `mindmap` 或用户指定形式。树状图难以表达的跨分支联系，补充带关系说明的表格或连线图。
- 思维导图用于整理已经解释清楚的联系；节点罗列本身不证明理解。

### 运用：模仿、总结自己的方法、实践与修正

1. **先模仿**：选择与目标相符的参考案例，复现关键步骤，并解释每一步为什么需要。
2. **总结自己的解题方法**：提炼输入、判断步骤、关键因素、方法选择、验收标准和适用边界。
3. **使用自己的方法实践**：逐步减少提示，在相同类型、条件有所变化的任务上使用自己的方法。
4. **根据问题修正方法**：对比预期与实际，定位错误判断、缺失前提或执行偏差，修正后再实践验证。

每次最小实践至少记录：任务与条件、采用的方法、预期结果、实际结果和证据、差异与下一步。用户尚未实践时只保留预测，不写成完成结果。

## 第五阶段：复盘迭代与方法归档

按用户指定的顺序处理实践暴露的问题：

1. **发现和定义问题**：将感受改写为可观察的预期与实际差异；说明问题的重要性，以及为什么值得解决。
2. **从多个角度拆分问题**：根据场景检查知识、方法、条件、输入、执行过程、资源、时序或反馈等因素；找到影响结果的关键因素和本质关系，不平均罗列所有角度。
3. **提出自己的方法并继续实践**：让用户提出判断或修正方法；必要时先给示范，再由用户解释和调整。写出假设、最小验证、预期现象与实际证据。
4. **分类汇总本次方法**：按问题类型与关键机制沉淀，供下一次同类问题检索、复用和再次验证。

形成一张可复用的方法卡：

```text
方法名称与分类：
要解决的问题及重要性：
适用场景和前提：
问题的本质与关键因素：
判断与操作步骤：
本次案例、结果和证据：
本次修正及其原因：
不适用条件与未解决问题：
下一次同类问题如何复用和检验：
```

方法未被实践检验时标为候选方法；当前案例成功时保留适用范围，不直接推导为普遍有效。归档的价值在于下一次能找回并用于判断。

## 连续学习与归档边界

- 本轮交接保留：目标及验收标准、当前阶段、已有产出与出处、暴露问题、当前方法、下一个行动。后续据此恢复，不把聊天次数当成掌握程度。
- 针对某个知识点的局部纠错与再练习交给 `knowledge-point-learning`；当问题影响知识取舍、学习顺序、时间分配或整体方法时，在本 Skill 中复盘调整。
- 整体目标与进度直接维护在同一份《学习进度与目标.md》中。方法卡可作为该文件的摘要或独立附件引用，不以每轮新建文件代替更新。
- 文件维护依靠宿主在当前会话读取和写入；未读取时不声称已恢复，未写入时不声称已同步，不声称后台自动跟踪用户的其他学习活动。
- 项目学习默认分析用户提供的源码和证据，实践由用户完成；代码修改、构建、烧录和外部发布按具体请求及已有授权处理，不因调用本 Skill 自动执行。
- 对项目和实践结论区分 `confirmed`、`user-confirmed`、`inferred`、`unverified`。静态分析、主机测试、交叉编译、目标板运行和仪器测量分别标明，不互相替代。
- 学习方法不预先绑定七天模板、固定复习间隔或十段教学输出；围绕用户目的、证据和当前阶段调整。
