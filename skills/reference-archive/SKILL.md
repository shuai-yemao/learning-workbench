# 参考资料归档

把本轮搜集到的参考资料整理成可复查清单。最终交付物必须是一份 Markdown 文件，不只在聊天里散落链接。每条必须带真实可用的链接；搜不到或打不开就直说。

## 先核链接，再入库

- 核实标题与 URL 一致，并尽量打开正文或页面。
- 在条目旁标明 `[已打开]`、`[API核实]` 或 `[仅搜索核实]`。
- 不收录失效链接、无法核对正文的付费墙、纯广告和没有实质内容的标题党页面。
- 同一内容有多个镜像时，优先官方或一手来源；只能使用镜像时，说明原域名状态。

## 按四类整理

每条统一写成：

```text
- [标题](URL)，作者、频道或仓库 owner，一句话说明内容或适用阶段，可信度，核实标记
```

### 视频教程

包括 B 站、YouTube 和公开课程。尽量记录合集或分集、时长或分 P 数、查询日播放量及发布或更新日期。

### 仓库链接

包括 GitHub、Gitee、GitCode 和厂商示例仓。尽量记录许可协议、大致 star、相关路径和引用的 Release。只确认存在但未读代码时，标明“仅核实仓库存在”。

### 博客文章

包括个人博客、技术专栏、官方应用笔记、用户手册在线页或 PDF。尽量记录站点、发布日期、系列序号和中英文版本关系。

### 论坛讨论

包括厂商社区、专业论坛、GitHub Discussions 和 Issues 中有结论的长帖。记录关键答主身份、官方回复、最佳答案和帖子状态；不整楼搬运。

## 可信度

| 档位 | 含义 | 常见来源 |
| --- | --- | --- |
| 高 | 一手官方或等价权威 | 原厂文档、应用笔记、官方培训、官方示例仓 |
| 中高 | 可核对的优质二手 | 厂商社区官方帖、活跃知名开源项目、成体系合作教程 |
| 中 | 需要交叉验证 | 专业论坛精华、带公式或代码的个人文章、实操视频 |
| 低／补充 | 只作线索 | 一般论坛回复、二手转载和摘要型视频 |

同一硬结论尽量由“高”或“中高”来源支撑。“低／补充”不能单独作为硬结论出处。疑似 AI 代写、与原厂资料冲突或无法打开的内容应降档或剔除，并说明原因。

## 文件位置与结构

优先使用用户指定的绝对路径。用户没有指定时，写入当前工作区的 `refs/<主题短横线slug>.md`。不要把用户资料写进学习台插件安装目录或 Skill 目录。

同一主题继续搜集时，打开原文件并按 URL、仓库或视频 ID 去重后追加，不另建近义文件。

文件保持以下结构：

```markdown
# <主题>参考资料

> 整理日期：YYYY-MM-DD（Asia/Shanghai）
> 说明：链接均经核实；未打开正文的条目已经标出。

## 要点摘要

- ...

## 视频教程

- ...

## 仓库链接

- ...

## 博客文章

### 官方文档

- ...

### 教程与专栏

- ...

## 论坛讨论

- ...

## 推荐阅读或观看顺序

1. ...

## 待复核／未收录

| 项 | 说明 |
| --- | --- |
| ... | ... |
```

写入后，聊天里只提供文件绝对路径和一两句摘要。用户明确要求时才把全文贴回聊天。

## 与学习台的边界

- 本 Skill 负责搜集、核实、分类、去重和保存资料，不负责教学、考试、评分或判断掌握度。
- AI 专题的短时动态搜集优先使用 `ai-info-gathering`；需要长期保存时再由本 Skill 接收已核条目并归档。
- 资料可以交给 `knowledge-point-learning` 作为学习输入，但“已经收集或阅读”不能算作用户掌握证据。
- 需要可视化时，用户应明确调用 `learning-visualization`。本 Skill 只准备中立资料，不把搜集和可视化混成一次隐式操作。
