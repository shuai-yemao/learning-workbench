# 学习内容可视化

把已经准备好的学习内容变成一个可检查、可交互的页面。像排版员整理现有材料一样工作：只调整呈现方式，不替作者补写事实。

## 1. 职责边界

只做这些事：

1. 读取用户明确给出的绝对文件路径或主题目录。
2. 判断现有内容是否值得可视化。
3. 把已有概念、例子、关系、步骤、代码、图片和来源整理成视觉结构。
4. 生成一个 HTML、一个 JSON 源描述，以及必要的资源或校验回执。
5. 检查文件、结构、交互和资源；有浏览器能力时再做浏览器检查。
6. 更新自己生成的同知识簇页面，并把旧版本放入同目录 `history/`。

不要做这些事：

- 不调用 `project-purpose`、`knowledge-point-learning`、`quick-concept-answer` 或任何其他 Skill。
- 不主动搜索网络，不筛选网络资料，不形成新的知识结论。
- 不补充专业知识、生活化例子、教学关系、步骤或来源。
- 不设计课程，不出题，不评分，不判断掌握度或学习进度。
- 不修改输入笔记，也不修改《学习进度与目标.md》。
- 不把页面生成成功说成学习完成。
- 不把模拟或动画说成真实硬件测量。

Archify 是可选命令行渲染器，不是被调用的 Skill。只运行其公开命令行程序；不要读取或执行 Archify 的 `SKILL.md`。Archify 不可用时继续使用内置后备渲染。

## 2. 输入门槛

用户必须给出以下一种绝对路径：

- 笔记文件；
- 主题文件夹；
- Markdown、JSON 或 YAML 内容包。

路径不存在时立即停止。不要创建猜测目录。输入是文件时，输出目录就是文件所在目录；输入是文件夹时，输出目录就是该文件夹。不要扫描其他主题目录，也不要向上递归查找。

文件夹输入只查看这一层中与主题直接相关的 Markdown、纯文本、C/C++、配置、JSON、YAML 和本地图片。先列出将读取的文件；文件较多或用途不清时，请用户指出主笔记或内容包。

读取网络资料的离线整理结果时，原样保留已有的标题、URL、读取时间和证据状态。不要打开 URL。

## 3. 先归一化，不补内容

运行内置脚本前，把明确存在于输入中的内容整理为 JSON。结构见 [中立内容包](references/content-package.md)。默认文件名为 `<主题短名>-visual.json`。

归一化规则：

- 每个字段都能回指输入文件和原文位置。
- `examples` 的角度、映射和边界必须来自输入。
- `relations`、`steps` 和 `spatial.items` 必须来自输入。
- 缺少当前输出形式必需的字段时，列出字段名并请用户补充。不要用常识补齐。
- 不确定文字是否属于事实时，放入 `unverified_items`，不要显示为已确认内容。

用脚本验证归一化内容：

```powershell
node <本Skill目录>\scripts\visualize.mjs validate <内容包绝对路径>
```

这条命令检查字段、引用关系和可视化门禁。在内容包所在目录运行。通过时会输出 JSON 结果；未通过时不会创建任何可视化文件。

## 4. 可视化门禁

以下条件至少满足两个才生成：

1. 有多个对象、步骤或关系。
2. 有因果、时序、空间、状态或方向变化。
3. 已有例子、抽象概念和实际对象需要对应。
4. 输入明确列出了容易混淆的关系。
5. 点击、切换、逐步揭示或参数展示能帮助看清现有内容。
6. 输入明确说明普通文字、代码或表格难以表达。

单个定义、简单公式、两个概念的简单区别、单个应用程序接口用途，以及一段文字已经说清的内容，默认不生成。

门禁不通过时：不创建 HTML、不创建 JSON、不创建历史备份。只报告未满足的条件或缺少字段。

默认每次最多新增一个可视化。同一知识簇已有本 Skill 生成的稳定文件时，优先更新；不要另建近似页面。

## 5. 选择渲染方式

按已有内容选择，不按页面是否“好看”选择。

| 已有内容 | 首选方式 |
| --- | --- |
| 多角度例子、概念、映射、边界、来源 | Archify `explainer` 或内置解释页 |
| 步骤和流程 | Archify `workflow` |
| 调用或时间顺序 | Archify `sequence` |
| 数据流向 | Archify `dataflow` |
| 状态变化 | Archify `lifecycle` |
| 特殊交互、参数变化 | 内置 HTML/SVG |
| 空间位置、方向、旋转、简单运动 | 内置简化三维；同时提供二维退路 |

用户明确指定输出形式时，以用户选择为准。没有必要使用三维时，使用二维。

### Archify 可用时

先运行：

```powershell
node <本Skill目录>\scripts\visualize.mjs probe-archify
```

这条命令检查 `C:\Users\zhang\.agents\skills\archify`，并确认版本属于 `3.2.x`。通过时会返回命令行入口和版本。

根据 [Archify 适配器](references/archify-adapter.md) 生成候选 JSON。候选内容只能来自归一化内容包。先运行 `compare-archify` 检查关键文字是否都进入候选，再运行 Archify `finalize`。不要复制 Archify 源码。

Archify 不存在、版本不兼容、类型不支持或 `finalize` 失败时，改用内置渲染。报告切换原因，不把失败说成通过。

### 内置后备渲染

```powershell
node <本Skill目录>\scripts\visualize.mjs render <内容包绝对路径> --out-dir <主题目录绝对路径> --basename <稳定短名>
```

这条命令生成独立 HTML、JSON 和校验回执。它只在门禁通过后写文件；更新已知文件前会备份。成功时会返回所有绝对路径。

## 6. 交互与三维限制

默认顺序是：已有例子 → 已有概念 → 已有过程或关系 → 已有实际对象或结果。

允许点击步骤、节点高亮、例子切换、展开说明、查看已有代码/配置/来源、二维与简化三维切换，以及展示已有参数。

页面不得自动出题、评分或判断掌握度。

简化三维只使用简单几何体、箭头、颜色和标签。页面必须标明“示意模型，不代表真实尺寸、材料或工程仿真”。三维显示失败时，二维视图仍应可读。

## 7. 文件与更新规则

稳定文件放在输入所在主题目录：

```text
主题目录/
├─ <短名>.html
├─ <短名>.json
├─ <短名>.visualization.json
├─ <短名>.archify.json       # 仅 Archify 输出需要
└─ history/
```

`<短名>.visualization.json` 是所有权与哈希回执，用来识别手工修改。已有文件缺少回执、生成器不匹配或哈希不一致时，停止并请求确认。不要覆盖来源不明或被手工修改的页面。

更新前运行 `preflight`。它只备份已确认属于本 Skill 且哈希一致的文件：

```powershell
node <本Skill目录>\scripts\visualize.mjs preflight <主题目录绝对路径> <稳定短名>
```

生成失败时保留稳定旧版本。不要把最终文件放到系统临时目录、插件安装目录或 `codex/`。

## 8. 验证

生成后依次检查：

```powershell
node <本Skill目录>\scripts\visualize.mjs verify <HTML绝对路径> <JSON绝对路径>
```

这条命令检查文件可读、回执哈希、嵌入内容、主要控件、资源引用和二维退路。通过时只证明文件与结构一致。

随后按能力补充验证：

1. 用浏览器打开 HTML，点击主按钮、步骤、节点和切换控件。
2. 检查窄屏与普通桌面宽度，没有明显空白、乱码和断链。
3. 简化三维要确认能显示、拖动和切回二维。
4. Archify 输出以 `finalize` 成功回执为准。

严格区分四类证据：文件/结构检查、页面交互检查、浏览器视觉检查、真实工程或目标板证据。没有人工看页面时，不说完成视觉验收；没有真实设备证据时，不说验证了硬件行为。

最后重新计算输入笔记哈希，确认它和《学习进度与目标.md》没有变化。

## 9. 最终回复

只报告：

- 是否生成；
- 渲染方式；
- HTML 绝对路径；
- JSON/YAML 绝对路径；
- 历史备份路径；
- 已通过的验证；
- 尚未验证的内容；
- 未生成时的原因。

不要附带完整课程，不做学习诊断，不把页面当作掌握证明。
