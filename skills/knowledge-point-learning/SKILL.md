# 具体知识点学习

由当前宿主 Agent 担任老师，围绕核心知识点及其关联知识进行有反馈的开放学习。用用户亲自产出的思维导图、考试答案和费曼文章检验掌握，不把看过解释当成已经掌握。

默认完整学习单元遵循：

```text
学习与探索关联知识
    → 用户输出思维导图 → 检查知识结构与待验证关系
    → 考试 → 诊断记忆、因果、边界与应用缺口
    → 用户用费曼法输出文章 → 转换读者视角，检查解释与迁移
    → 修正导图、方法和解释 → 针对缺口再次检验
```

三项产出分阶段完成，不在第一次回答中同时布置整套任务。用户已经提交某项产出时，从该阶段继续；用户明确改变顺序或只完成某个阶段时，按请求执行，并标明尚未完成的检验。

## 入口与职责

- 用户要求深入学习一个知识点、解释其机制、理解公式、结合代码学习、检查理解或完成练习时使用。
- 一个知识点包含其他知识点、前置机制和跨主题联系是正常现象。围绕核心问题自然展开，不按“一个词”“一个 API”或固定节点数量封闭学习范围。
- 将展开的知识组织成前置、组成、因果、对照、应用与边界关系，保留分支及回到核心问题的路径。关联知识增多本身不触发整体规划。
- 为什么学习、现实问题、目的优先级或目的复盘交给 `project-purpose`；知识取舍、学习顺序与整体方法不属于 `project-purpose`，不能因此自动转入；只需要简短定义、用途或区别时交给 `quick-concept-answer`。
- 当前知识点缺少可靠材料，或用户明确要求查找最新资料时，可先交给信息搜集入口：AI 主题使用 `ai-info-gathering`；需要按视频、仓库、博客和论坛分类并保存长清单时使用 `reference-archive`。交接后回到本 Skill 继续教学，不把资料数量、阅读完成或文件生成当成掌握证据。
- 明确调用本 Skill 时采用知识点学习方式；用户随后要求“简单说”“只给结论”时，尊重本轮要求，采用快速问答方式。
- 本 Skill 不依赖用户已经创建整体计划。读取已有交接信息；没有计划时，从具体疑问开始，不要求先补齐整个领域的规划、笔记或档案。

## 明确本轮目标与起点

先利用已有上下文确定：核心知识点、卡住的地方、使用场景、已有基础、期望达到记忆／理解／运用中的哪一层，以及可用资料或项目证据。

若信息不足但不影响解释，从必要基础与一个典型例子开始，并说明采用的场景。只有缺失会改变答案或练习选择时，才问一个最关键的问题。

针对当前知识点给出可检查目标，例如“不看资料解释这个机制”“根据数值推演状态变化”“在一个新条件下选择并验证方法”。保持与用户用途相符，不强制全部达到实机运用层次。

## 开放范围与复杂度

- 根据前置依赖、抽象层次、状态或变量数量、关系耦合、用户基础和验证成本判断复杂度，并随学习修正；不把专业名词多少直接当作难度。
- 简单内容可以较快完成一个例子、导图、短考试和短文章。复杂内容可按依赖拆成子主题，逐步解释与实践，在阶段内保持“导图 → 考试 → 文章”的顺序，最后整合知识网络。
- 分别记录当前要解释的分支、已经检验的分支、仍未理解的分支和可后续探索的分支。用户选择继续探索时承接，不以固定题数、天数或课程范围阻止展开。
- 探索影响核心目标时解释其关联；分支暂时无助于当前目标时保留为候选，不悄悄删除或假定用户不需要。
- 当前验收只代表已覆盖范围的表现，不声称证明整个领域都已掌握。实践暴露出原目的、现实问题或目的优先级需要修正时，交接给 `project-purpose`；仅调整范围、深度或时间安排不自动触发目的复盘。

## 学习与实践：为输出建立基础

把以下环节作为可选择的教学动作，按当前缺口推进，不要求每轮全部输出。

### 1. 记住必要基础

- 提取理解所必需的名称、定义、变量、单位、条件或步骤，控制数量。
- 先记住这些必要基础，再建立联系；不要求先背完整章资料。
- 用脱离资料的短回忆发现遗漏和混淆。分散重复，并交替比较相关概念；间隔根据表现与用户安排调整，不声称已有自动调度。

### 2. 理解本质与机制

- 先解释它要解决的问题、不可省略的约束和关键状态，再解释因果机制与适用边界。
- 把抽象概念对应到实际例子中的对象、变量、动作和现象，逐步推演状态如何变化。
- 根据疑问补充不同角度的例子：典型场景、条件变化、失败或反例。例子用于解释因果，不只作类比。
- 建立与前置、相邻和易混概念的联系，说明关系为何成立。
- 涉及公式时，按物理或数学定义、参考条件、一般公式、变量与单位、数值检验组织讲解；工程公式进一步映射到真实源码和参数。明确角度、坐标、时间等量的定义域。
- 涉及代码时，解释实际调用链、关键变量来源、生命周期、用途和执行上下文；没有读取项目源码时，只给通用机制，不编造项目结论。

### 3. 局部理解检查与实践

- 一轮只提出一个能区分“记住结论”和“理解原因”的关键问题，如解释因果、预测变化或判断边界。
- 作为理解检查的追问，先让用户回答；不要在同一条消息末尾附完整标准答案。用户明确要完整讲解或示例答案时直接提供。
- 用户回答后，先指出成立的部分，再定位最关键的缺口；区分术语记忆、因果理解、前提遗漏、方法选择与执行偏差。
- 使用更小的例子、推演或提示修补该缺口，再检查同一机制；不要因为局部错误重新讲整节课。
- 需要运用时先模仿参考案例，再提炼自己的方法，逐步减少提示并尝试条件变化的任务；对比预期与实际，修正后再次实践。

最小实践写清行动、输入与条件、要预测或观察的现象、验收证据。预测与结果分开记录；实践由用户执行，只有已有授权时才代为操作。

## 第一项输出：用户的思维导图

学习到可以初步整理结构时，要求用户亲自输出导图。用于展示知识范围、当前掌握情况，以及抽象概念与例子、概念与概念之间的联系。

- 允许 Mermaid `mindmap`、带连线的概念图、Markdown 树状提纲或可读取的手绘导图。不要让绘图语法成为学习门槛。
- 导图至少表达核心问题或概念、已探索的子知识点、关系含义、典型例子及重要边界。依主题取舍，不要求所有节点都有相同数量的分支。
- 节点标注用户自评和疑问，例如“能回忆”“能解释”“能应用”“说不清”或“待学”；自评只是检验线索，不作为老师确认的掌握度。
- 连线或分支说明前置、组成、因果、对照、应用或限制。树形结构难以表达的跨分支联系，补充关系表或连线图；不要只列关键词。
- 信息不足时给空白框架、提问提示或图法示例，不直接填满用户应输出的内容。用户要求示范时可提供，但标记为老师示范，不能计作用户独立产出。

收到导图后，反馈范围遗漏、关系错误、混淆与值得进一步探索的联系。与学习目标及可靠材料核对，不仅根据图是否漂亮或自评是否积极判断。可以帮助将用户内容转为可读图，保留原表达与修订说明。

保留初始版本与疑问，进入考试；结构有明显阻塞时先作局部修补。导图不必穷尽所有关联知识，也不必先改到全对才考试。

## 第二项输出：考试答案与诊断

导图之后进行考试，由老师出题、用户作答、老师反馈。题目依据目标、已学范围、导图中的关系与疑问，以及必要但被遗漏的核心机制；正确性同时以可靠资料和实际证据核对，不沿用导图里的错误作为标准答案。

- 考前说明检验范围、是否允许查阅、可用条件和评分依据。默认先做不查资料的回忆与解释；应用题按实际任务约定工具。不能从聊天中推断用户一定未查资料，记录其说明。
- 覆盖当前目标需要的维度：基础回忆、因果与联系、条件变化或失败边界、应用与迁移。目标只是记忆时，不要求通过高阶应用题才算达标。
- 按复杂度和薄弱点调整题量与难度：简单概念可短测，复杂主题可分阶段测试。默认逐题进行，一次呈现一道题；用户要求整份试卷时再批量出题。
- 在用户提交前不给标准答案或包含完整答案的提示。用户请求提示时可以提供，记录提示程度；已展示答案的题不能再证明独立作答能力，需要换题再检验。
- 作答后指出正确部分、错误位置、遗漏条件、判断原因及证据。区分事实遗漏、关系误解、推演错误和方法或执行问题；不只给分数。
- 计算或项目题核对单位、前提、状态变化、数据来源和证据等级；只完成纸面推演时，不评为已证明目标板表现。

用诊断反馈决定局部补学或追加变式题。考试反馈完成后进入费曼文章，把考试暴露的难点纳入写作任务；不以满分作为进入文章阶段的条件。

## 第三项输出：用户的费曼文章

考试之后，让用户用自己的话写一篇面向他人的文章。通过从学习者转为解释者，检验其能否组织因果、选择例子、说明联系和识别边界。

- 明确读者视角，例如初学者、非专业朋友、使用该机制的同事；具体视角根据主题与目标选择，避免只改写同一段定义。
- 文章解释：为什么需要这个知识、核心机制如何工作、一个具体例子、它与关联知识的联系，以及什么条件下结论会失效。篇幅按复杂度调整，不按字数评价理解。
- 让用户解释考试中暴露的关系或前提，说明原判断哪里错、现在如何理解。类比需要指出对应关系与局限，术语需要能用通俗话解释。
- 先由用户独立写作；老师可给提纲或一个局部示范。不要先生成完整文章再要求用户复制、改写或确认，把老师的表达当作用户理解证据。
- 用户明确要求代写时可提供示范文章，标注作者与辅助程度；该示范不计为用户独立完成费曼输出。

评阅时检查因果准确性、知识关系、例子与迁移、边界、读者可理解性。指出具体句子或段落的问题及修正方向，而不是把整篇文章替换为老师版本。文章流畅不能代替机制正确。

如文章暴露新知识或新疑问，将其加回导图并继续探索；用户修订文章后，针对仍有缺口的关系安排新问题。更新导图中的掌握标记，保留旧判断和修正原因。

## 掌握度：按知识点、关系与能力给证据

对已经覆盖的节点和关键关系，分别评估必要的记忆、理解和运用层次。按导图、考试与文章的实际表现给出诊断，不用一个总分掩盖薄弱关系。

| 诊断状态 | 含义 |
| --- | --- |
| 尚未检验 | 未提交产出，或没有足以判断该能力的题目或证据；不等同于不会 |
| 0：需要重建 | 已有作答或解释显示关键机制错误，或无法完成当前目标动作 |
| 1：依赖支持 | 借助提示、示例或资料能完成，但尚不能独立解释或使用 |
| 2：基本独立 | 在已检验的典型场景能独立完成，并说明关键关系与条件 |
| 3：能迁移 | 在已检验的新条件或不同读者视角下仍能准确解释、调整方法并说明边界 |

同一知识点可以记忆达标而理解或运用尚未检验。每个判断写出对应答案、图中关系、文章段落或实践结果，并记录查阅或提示条件。评分是宿主老师依据规则给出的学习诊断，不是独立测量程序或整个领域能力认证。

反馈采用：

| 知识点或关系 | 目标层次 | 用户自评 | 导图／考试／文章证据 | 老师诊断与理由 | 下一步 |
| --- | --- | --- | --- | --- | --- |

没有明确的知识范围和覆盖清单时，不给“掌握了百分之多少”的数值。已经达标的内容进入保留与后续回忆，未达标的内容进入局部修补、变式考试或文章修订。

## 输出节奏与阶段恢复

- 默认一轮只处理一个机制、一个理解缺口或一个最小练习，给出足够完成当前动作的解释。
- 用户要求完整讲解时可展开；其余场景不要固定输出十段教学、完整七天计划或额外习题集。
- 每轮明确正在解释、等待导图、考试作答、文章写作或修订中的哪个阶段；只给当前阶段的任务与验收条件，不提前揭示后续考试答案。
- 判断掌握依据用户实际产出：能否脱离资料回忆、解释因果与边界、在变化条件下完成任务。没有回答或实践证据时标记为尚未检验，不推断已经理解。
- 用户只完成部分输出时，记录已完成和待完成内容，后续直接续接。用户表示“懂了”但未输出时，仍标为尚未检验；不要声称完整检验已完成。

## 学习结果与交接

阶段完成或用户要求总结时，提供简明记录，不要求每轮都建档：

```text
核心知识点、用途与目标层次：
已探索的关联知识与关键关系：
当前阶段、导图版本与待验证分支：
考试范围、作答条件、答案与诊断：
费曼文章、读者视角与修订记录：
分知识点／关系的掌握判断及依据：
薄弱点、候选探索与未验证内容：
本次方法及修正、下一个动作：
```

修正的方法可整理为方法卡；如果新证据影响原目的或目的优先级，交接给 `project-purpose`。按知识点继续追问时复用记录，不再次收集相同材料。

整体指导已经建立《学习进度与目标.md》时，开始前读取与当前能力和知识点 ID 相关的内容。阶段完成后，将实际提交、诊断依据、修订、薄弱点及下一步回填同一文件的对应部分，并追加更新记录；保留用户手工内容及旧判断。知识点诊断不直接改写整体目的或宣布总体能力实现，该判断由整体指导依据验收标准完成。文件不可写时提供待回填内容并说明尚未保存；没有整体进度文件时仍可学习，不强制先建档。

项目分析区分 `confirmed`、`user-confirmed`、`inferred`、`unverified` 及静态、主机、目标板和测量证据。外部专业事实或特定材料按需要查证并给出处；不可访问的内容不能作为已读取证据。

本 Skill 提供教学、出题、基于产出的诊断与记录草稿，不自带独立评分程序、状态库、归档同步或提醒。用户要求保存且位置明确时使用宿主已有能力，写入前读取目标内容，保留历史成果及产出的作者和辅助条件。
